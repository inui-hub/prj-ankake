## 品質評価

| 観点 | 評価 | 根拠 |
|---|---|---|
| 型安全・不変性 | 良好 | strict TypeScript、readonly 型、オブジェクトスプレッドによる state 更新 |
| テスト基盤 | 良好 | Vitest、fast-check、domain/app/UI のテスト配置 |
| 共鳴のテスト網羅 | 要改善 | 現在は 0–10 範囲の性質テストと召喚イベント中心。仕様との差分・効果・遷移を検証していない |
| レイヤ分離 | 良好 | UI／アプリ／domain／永続化を workspace で分離 |
| リント・CI | 要改善 | ESLint 設定、CI ワークフロー、coverage 設定を確認できない |
| 文書化 | 普通 | 日本語の詳細仕様はあるが、実装 README は限定的 |

## 共鳴の高リスク欠落

- 召喚加算が `currentCost` と `max(1, ...)` に依存し、仕様の `min(cost, 3)` に一致しない。
- スタンバイ減衰、スペルの 3 レーン加算、5 以上の状態遷移、5 属性の効果、固定処理順、使用回数がない。
- `PublicBattleView` と `BattleInfoPanels` が共鳴を持たないため、詳細画面仕様の値・状態・使用可否を満たせない。
- `resonance.changed` に機械可読な前後値・理由・閾値遷移がなく、利用者向けログと UI フィードバックを安定して検証できない。

## 必須の検証境界

domain 単体テストでは加減算、5/4 の遷移、元コスト上限、スタンバイの side 限定、各属性効果、使用回数、右→中央→左・火→水→風→光→闇の順を検証する。fast-check では任意の command 列で範囲、使用回数、解除後の修正消滅を確認する。アプリ／UI テストでは公開投影、共鳴パネル、プレイヤーのみの操作可否、構造化イベントのログ表示を確認する。
