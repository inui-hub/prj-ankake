## Intent Analysis

プレイヤーがメニュー、デッキ構築、対戦中に必要な情報を一貫した言語と視認性で扱えるようにする。既存のゲーム規則を変えず、画面表示と既存操作の到達性を改善する。

## Functional Requirements

### FR-1 言語選択

- システムはメニュー画面に日本語・英語を切り替える操作を提供しなければならない。
- システムは起動時に日本語を選択状態にしなければならない。
- 選択言語は現在の起動中だけ保持し、再読み込みまたは次回起動時には日本語へ戻らなければならない。
- システムはメニュー、デッキ構築、対戦画面を含むプレイヤー向け画面文言を選択言語で表示しなければならない。
- システムはソートなどの画面ラベルも選択言語で表示し、内部の値や並び順の意味は変更してはならない。

受入基準:

- Given 日本語が選択されている、When 各画面を表示する、Then プレイヤー向け文言は日本語である。
- Given 英語が選択されている、When 各画面を表示する、Then プレイヤー向け文言は英語である。
- Given 日本語が選択されている、When デッキ構築画面で既定ソートを表示する、Then `cost:asc` の意味を保った `コスト昇順` を示す。
- Given 英語が選択されている、When デッキ構築画面で既定ソートを表示する、Then `cost:asc` の意味を保った `Cost up` を示す。
- Given 英語が選択されている、When アプリケーションを再読み込みする、Then 言語は日本語に戻る。

### FR-2 カード効果のローカライズ

- システムは選択言語に対応するカード効果説明を表示しなければならない。
- 効果のゲーム規則の識別・実行は、表示言語の文言に依存してはならない。
- カタログ、手札、盤面、カード詳細の各表示経路は同じ選択言語の効果説明を用いなければならない。

受入基準:

- Given 英語が選択されている、When 効果を持つカードをデッキまたは対戦画面で確認する、Then 効果説明は英語である。
- Given 英語が選択されている、When カタログ、デッキ構築のカード一覧、手札、盤面、カード詳細を表示する、Then 同一カードの効果説明はすべて英語である。
- Given 日本語と英語を切り替える、When 同一カードを表示する、Then 効果の意味とゲーム挙動は変わらず、表示文言だけが変わる。

### FR-3 デッキ構築の既定ソート

- システムはデッキ構築画面を開いたとき、カード一覧を `Cost up`（コスト昇順）で並べなければならない。
- システムは検索・フィルターのリセット後も同じ既定ソートを適用しなければならない。

受入基準:

- Given デッキ構築画面を開く、When カード一覧が表示される、Then ソート選択は `Cost up` であり、一覧はコスト昇順である。
- Given 検索条件をリセットする、When 一覧が更新される、Then ソート選択は `Cost up` である。

### FR-4 レーンと拠点の視認性

- システムは対戦盤面の左・中央・右レーンを、既存テーマ内で相互に区別できる背景色で表示し、各マスに対応する意味的なclassまたはdata属性を付与しなければならない。
- システムは拠点マスで拠点名の代わりに拠点アイコンと耐久値を表示しなければならない。
- システムは拠点の制圧状態を中立・味方・敵で区別できるマス色として表示し、各状態を示す意味的なclassまたはdata属性を付与しなければならない。
- 隣接するレーンまたは制圧状態の背景色は異なり、文字・アイコンとのコントラストは4.5:1以上でなければならない。

受入基準:

- Given 対戦盤面を表示する、When 各レーンを見る、Then 左・中央・右を背景色で識別できる。
- Given 対戦盤面を表示する、When 各マスのDOMを確認する、Then 左・中央・右に対応する属性を持つ。
- Given 隣接するレーンまたは制圧状態を表示する、When 背景色と前景を測定する、Then 状態ごとの背景色は異なり、文字・アイコンとのコントラストは4.5:1以上である。
- Given 拠点マスを表示する、When 制圧状態が中立・味方・敵のいずれかである、Then 拠点名は表示せず、アイコン・耐久値・対応する状態色を表示する。
- Given 拠点マスを表示する、When 制圧状態が中立・味方・敵のいずれかである、Then 対応する状態属性を持つ。

### FR-5 カード詳細の即時表示

- システムは手札と盤面のカードにポインターを置いている間、カードのイラスト、名称、スタッツ、移動力、効果を表示しなければならない。
- システムは同じ詳細をキーボードフォーカスでも表示しなければならない。
- 詳細表示は既存のカード選択・盤面操作を妨げてはならない。

受入基準:

- Given 手札または盤面にカードがある、When カードにホバーまたはキーボードフォーカスする、Then 必要な5項目を含む詳細が表示される。
- Given 詳細が表示されている、When カード操作を実行する、Then 既存の操作が実行できる。

### FR-6 共鳴値の表形式表示

- システムは対戦画面の共鳴値を5行3列の表で表示しなければならない。
- 行は `fire`、`water`、`wind`、`light`、`dark` の順の属性、列は左・中央・右レーンの順を表さなければならない。
- 各セルは対応する属性・レーンの現在の共鳴値を表示しなければならない。

受入基準:

- Given 対戦画面を表示する、When 共鳴値パネルを確認する、Then 5属性×3レーンの15セルが表示され、それぞれの値が対応する投影値と一致する。

### FR-7 水共鳴の盤面直接選択

- システムは水共鳴で移動力を増加できる盤面上のクリーチャーを、盤面上で分かる状態にしなければならない。
- システムは水共鳴モード中にプレイヤーが対象クリーチャーを盤面で1回クリックした時点で、既存の水共鳴コマンドを実行しなければならない。
- システムは水共鳴モードを解除する操作を提供し、対象をクリックする前に解除した場合はコマンドを実行してはならない。水共鳴の盤面操作はキーボードでも対象を選択・実行できなければならない。
- システムは水共鳴の対象と対象外をdata属性で区別し、対象を視覚的にハイライトしなければならない。
- システムは不正な対象を選べず、既存のドメイン検証を維持しなければならない。

受入基準:

- Given 水共鳴が使用可能で対象クリーチャーがいる、When プレイヤーが対象を盤面でクリックする、Then そのクリーチャーの移動力が既存規則に従って増加する。
- Given 水共鳴モード中で対象をまだクリックしていない、When プレイヤーがモードを解除する、Then 水共鳴コマンドは実行されない。
- Given 水共鳴モードを開始する、When 盤面を表示する、Then 対象は `data-water-resonance-target` 属性と視覚的ハイライトを持ち、対象外は対象属性を持たない。
- Given 水共鳴モード中でキーボードフォーカスが対象カードにある、When 実行操作または取消し操作を行う、Then 対象では既存コマンドが1回実行され、取消しではコマンドは実行されない。
- Given 水共鳴が使用不可または対象外のカードである、When 盤面を操作する、Then 増加コマンドは実行されない。

## Non-Functional Requirements

- NFR-1: 新設・更新するプレイヤー操作はマウスとキーボードフォーカスで到達できること。
- NFR-2: 言語切替、カード詳細、盤面選択、既定ソートは自動テストで回帰を検出できること。
- NFR-3: `npm run typecheck` および `npm run test` を通過すること。追加した言語切替、効果文表示経路、既定ソート、レーン/拠点属性、カード詳細、水共鳴操作には回帰テストを追加すること。
- NFR-4: `web → ui → domain` の依存方向を維持し、表示言語の変更がゲーム規則を変更しないこと。

## Constraints

- React、TypeScript、Vite、npm workspacesの既存構成を維持する。
- 外部翻訳サービス、サーバー、認証機能は追加しない。
- 言語設定は永続化しない。
- 既存の対戦規則、IndexedDBのデッキ保存、CPU戦略は変更対象外とする。

## Assumptions & Open Questions

### Assumptions

- カード名・属性名・既存ゲーム規則に関するデータは、日本語・英語の表示に必要な対応情報を追加できる。
- 拠点アイコンは既存のアセット管理方式に沿って追加できる。

### Open Questions

None.
