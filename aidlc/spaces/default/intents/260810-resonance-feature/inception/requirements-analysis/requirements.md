# 共鳴機能要件

## Intent analysis

既存の Battle Domain と対戦画面へ属性共鳴を統合し、プレイヤーと CPU が同じルールで共鳴状態と効果を扱い、プレイヤーが値・状態・使用状況を確認できるようにする。成功条件は、値の増減、閾値、5属性効果、固定処理順および画面表示を自動検証できることである。

## Functional requirements

### 共鳴値とカード・ターン処理

- `FR-1`（Must）: 各プレイヤーは左・中央・右の各レーンと火・水・風・光・闇の各属性の組合せ、計15個の共鳴値を独立して保持する。初期値は0、各セルの許容範囲は0〜10とする。属性間およびレーン間で値を合算しない。
- `FR-2`（Must）: 値の増加量は常に `min(カードの元コスト, 3)` とし、現在コスト、コスト変更後の値、実際に支払った PP を参照しない。増減の結果は各セルを `0..10` にクランプし、10を超える分は切り捨て、0未満にはしない。
- `FR-3`（Must）: 手札からクリーチャーカードを召喚したとき、召喚確定、盤面配置、召喚時効果の解決の後、**召喚先として確定したマス**のレーンの同属性セルへ FR-2 の増加量を一度だけ加算し、直後に共鳴状態を更新する。移動後のレーンへ値を移さない。カード効果、能力、コピーその他カードとしてプレイされずに出現したクリーチャーは値を増加させない。
- `FR-4`（Must）: 手札からスペルカードを発動したとき、スペルの属性について、左・中央・右の各レーンの同属性セルへ FR-2 の増加量をそれぞれ一度ずつ加算し、直後に共鳴状態を更新する。今回のスコープでは、スペルの発動自体とこの共鳴増加のみを解決し、スペル本文の固有効果、対象選択およびその結果は解決しない。無効化されたカードプレイ、移動、攻撃その他の非プレイ行動は値を増加させない。
- `FR-5`（Must）: 自分のスタンバイフェーズ開始時に、自分の15セルをそれぞれ1減少させて `0..10` にクランプし、各セルの共鳴状態を直ちに再評価する。相手のターン開始時には減少させない。値が5以上なら当該プレイヤーの当該レーン・属性は共鳴中、4以下なら非共鳴とする。共鳴効果は誘発一回ではなく、共鳴中だけ適用され、5への到達で開始、4への低下で終了、再度5以上で再開する。同じ属性の再加算で重複しない。

### 属性別共鳴効果

- `FR-6`（Must、火）: 火共鳴中は、そのレーンの全味方クリーチャーの攻撃力を常に `+1` とする。クリーチャーがレーンを移動した場合は移動先・移動元の共鳴状態に応じて即時に適用または解除し、火共鳴が4以下になれば補正を直ちに終了する。火効果は対象選択・使用回数・リセットを持たない。
- `FR-7`（Must、水）: 自分のターン中に、水共鳴中の各レーンにつき一度、その同一レーン上の味方クリーチャー1体を選択し、そのターン中の通常移動の最大距離を `+1` する。これは追加の移動権を与えず、他の移動力変更とは重複でき、増加後の距離で別レーンへ移動できる。使用済みはレーンごとに管理し、自分の各ターン開始時に未使用へ戻す。ターン終了時に移動力 `+1` を解除する。非共鳴、水以外のレーン、相手ターン、存在しない対象、敵または別レーンの対象、同ターン使用済みレーンでは使用できない。
- `FR-8`（Must、風）: 自分のターン中に、風共鳴中の各レーンへカードとして最初に召喚するクリーチャーの使用コストを `1` 減らし、現在コストは `1` 未満にしない。他のコスト軽減とは重複できるが、元コストは変更せず、FR-2〜FR-3 の共鳴増加量も元コストで算出する。使用済みはレーンごとに管理し、自分の各ターン開始時に未使用へ戻す。効果によって出現するクリーチャー、同じレーンの当ターン2体目以降の召喚、非共鳴レーンには適用しない。
- `FR-9`（Must、光）: 自分のアタックフェーズ終了時、光共鳴中の各レーンについて、そのレーン上の全味方クリーチャー、およびそのレーンに存在する自分が制圧済みの中立拠点をそれぞれ `1` 回復する。さらに自分のプレイヤー拠点を、光共鳴中の各レーンごとに `1` 回復する。回復は最大体力を超えず、未占領または相手所有の中立拠点および相手アタックフェーズ終了時は対象外とする。光効果は対象選択・使用回数・リセットを持たない。
- `FR-10`（Must、闇）: 闇共鳴中の各レーンについて、各プレイヤーのターンごとに一度、そのレーン上の自分のクリーチャーが最初に破壊されたとき、破壊処理の完了後に破壊されたマスへ闇属性 `1/1/1` トークンを1体出す。原因は戦闘、スペル、能力を問わない。使用済みはレーンごとに管理し、闇共鳴へ遷移した時点、および各プレイヤーのターン開始時に当該レーンが闇共鳴中の場合に未使用へ戻す。ただし、同一ターンで使用済みになった後に闇共鳴が解除・再成立しても回復しない。トークン配置時にそのマスが使用不能なら出さず、効果出現のトークンは共鳴値を増加させない。共鳴前の破壊は遡及せず、共鳴解除後も既に出たトークンは残る。

### 同時処理と対戦画面

- `FR-11`（Must）: 複数属性が同じレーンで共鳴中なら、相互に無効化せず全効果を適用する。同一 transaction で複数の共鳴効果を適用・解除・再計算する場合は、ターンプレイヤー、非ターンプレイヤーの順に処理し、各プレイヤー内では右、中央、左レーンの順、各レーン内では火、水、風、光、闇の順に処理する。
- `FR-12`（Must）: 対戦画面の共鳴情報領域は、プレイヤーとCPUをタブで切り替え、選択した側の15セルを「行: 火・水・風・光・闇」「列: 左・中央・右」の3列×5行表で表示する。各セルは値 `0..10`、共鳴中（5以上）の視覚的強調、効果の使用可否または使用済み状態を対戦状態と一致させて表示する。
- `FR-13`（Must）: 共鳴中セルを選択したとき、対応する効果の簡易説明を共鳴表の下部または隣接領域に表示する。プレイヤーが任意に使用する水効果だけは、プレイヤー自身のターン、プレイフェーズ、対象レーンが水共鳴中かつ未使用の場合に操作を提示し、選択後は対象選択へ移行する。自動適用の火・風・光・闇には使用ボタンを表示しない。CPU情報タブおよびCPUターン中には、プレイヤーが操作できる共鳴効果ボタンを表示しない。
- `FR-14`（Should）: 共鳴値の増減、共鳴状態の開始・終了および闇・水・風の使用状態の変化を、表示モデルと戦況ログへ反映する。5以上への遷移では当該セルを短時間強調し、4以下への遷移では強調を解除してログへ表示する。

## Non-functional requirements

- `NFR-1`: 共鳴に起因する加算、減衰、閾値遷移、効果、使用済み状態、トークン配置は、UIやCPUが状態を書き換えるのではなく、`GameEngine.submitCommand` 配下の不変 `BattleState` transaction として一貫して解決する。人間とCPUは同一の command 検証・ルールを通る。
- `NFR-2`: `resonance.changed` イベントは、少なくとも `side`、`lane`、`attribute`、`before`、`after`、`reason`、`becameActive`、`becameInactive` を構造化 `data` として公開する。対象選択型の水効果は `side`、`lane`、`attribute`、対象クリーチャー instance ID を含む command とし、domain がターン、共鳴、レーン、対象、未使用を検証する。`projectPublicBattleView` は各セルの値、共鳴中、効果種別、ターン内使用状態、人間プレイヤーの操作可否を投影し、UI はその投影とイベントを使用して画面とログを更新する。
- `NFR-3`: 自動テストは、0/10クランプ、元コスト1・2・3以上、コスト変更・実支払PPからの独立、クリーチャーの1レーン加算、スペルの3レーン加算と固有効果非解決、非プレイ出現の非加算、スタンバイ減衰、閾値開始・終了・再開、5属性効果、レーン別使用とリセット、FR-11の固定順、イベント payload、投影、FR-12〜FR-14のUI操作可否を検証する。

## Constraints

- ブラウザ内で完結し、外部サービスと新規インフラを追加しない。
- スペルは発動して共鳴値を増加させるが、スペル固有効果は今回解決しない。

## Out of scope

- 共鳴以外のゲーム機能とUI全面刷新。
- スペル固有効果の解決、対象選択、および結果処理。
